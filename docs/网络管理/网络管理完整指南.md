## 网络架构

### 架构原则

#### 基础设施被动，业务应用主动

- **基础设施组件**（MySQL, Redis, MongoDB, Nginx, Kafka, NSQ）
  - ✅ 只连接 `infra-network`
  - ❌ 不连接任何业务网络
  - 作用：被动等待业务应用访问

- **业务应用**
  - ✅ 连接自己的业务网络（如 `miniblog-network`）
  - ✅ 同时连接 `infra-network` 访问基础设施
  - 作用：主动连接所需资源

### 网络类型

```text

| 网络名称 | 类型 | 范围 | 用途 |
|---------|------|------|------|
| `infra-network` | overlay | 172.20.0.0/16 | 基础设施共享网络 |
| `<app>-network` | bridge/overlay | 172.21+.0.0/16 | 业务应用专用网络 |

### 为什么这样设计？

#### 单向依赖原则

```text
业务应用 ──→ 基础设施
   ✓          ✓
可变化      不可变化
```

业务应用会频繁变更（新增、删除、重命名），基础设施相对稳定。如果让基础设施组件配置业务网络，每次业务变更都要修改基础设施配置，非常麻烦且容易出错。

#### 示例对比

❌ **错误方式**（基础设施主动连接业务网络）

```yaml
# MySQL docker-compose.yml
services:
  mysql:
    networks:
      - infra-network
      - miniblog-network  # ❌ 不应该在这里配置
      - blog-network      # ❌ 每增加一个业务都要改
      - shop-network      # ❌ 基础设施组件变得臃肿
```

✅ **正确方式**（业务应用主动连接基础设施网络）

```yaml
# miniblog docker-compose.yml
services:
  miniblog-app:
    networks:
      - miniblog-network   # ✅ 自己的业务网络
      - infra-network      # ✅ 访问基础设施

networks:
  miniblog-network:
    external: true
  infra-network:
    external: true
```

## Makefile 快速命令

### 业务网络管理

```bash
# 创建网络
make app-network-create NAME=miniblog-network                    # bridge网络
make app-network-create NAME=app-net DRIVER=overlay              # overlay网络
make app-network-create NAME=app-net SUBNET=172.21.0.0/16        # 自定义子网

# 管理网络
make app-network-list                                             # 列出所有网络
make app-network-inspect NAME=miniblog-network                   # 查看详情
make app-network-delete NAME=miniblog-network                    # 删除网络
```

### Docker Swarm 管理

```bash
# 初始化集群
make swarm-init ADVERTISE_ADDR=192.168.1.100                     # 初始化管理节点
make swarm-join MANAGER_IP=192.168.1.100                         # 加入工作节点
make swarm-join MANAGER_IP=192.168.1.100 NODE_TYPE=manager      # 加入管理节点

# 管理集群
make swarm-status                                                 # 查看集群状态
make swarm-nodes                                                  # 列出所有节点
make swarm-network                                                # 创建overlay网络
make swarm-leave                                                  # 离开集群
```

### 参数说明

| 参数 | 必需 | 默认值 | 说明 |
|------|------|--------|------|
| NAME | ✅ | - | 网络名称 |
| DRIVER | ❌ | bridge | 网络驱动（bridge/overlay） |
| SUBNET | ❌ | 自动 | 子网范围（如 172.21.0.0/16） |
| GATEWAY | ❌ | 自动 | 网关地址 |
| INTERNAL | ❌ | false | 是否为内部网络 |
| ATTACHABLE | ❌ | false | overlay是否可附加 |
| ENCRYPTED | ❌ | false | overlay是否加密 |
| ADVERTISE_ADDR | ✅ | - | Swarm管理节点IP |
| MANAGER_IP | ✅ | - | Swarm管理节点IP |
| NODE_TYPE | ❌ | worker | 节点类型（worker/manager） |

## 业务网络管理

### 使用底层脚本

如果需要更多控制，可以直接使用脚本：

```bash
# 创建网络
bash scripts/network/app-network-manager.sh create \
  --name miniblog-network \
  --driver bridge \
  --subnet 172.21.0.0/16 \
  --gateway 172.21.0.1

# 列出网络
bash scripts/network/app-network-manager.sh list

# 查看详情
bash scripts/network/app-network-manager.sh inspect --name miniblog-network

# 删除网络
bash scripts/network/app-network-manager.sh delete --name miniblog-network

# 连接容器到网络
bash scripts/network/app-network-manager.sh connect \
  --name miniblog-network \
  --container miniblog-app

# 断开容器
bash scripts/network/app-network-manager.sh disconnect \
  --name miniblog-network \
  --container miniblog-app
```

### 网络规划建议

```bash
# 基础设施: 172.20.0.0/16 (已使用)
infra-network

# 业务网络: 从 172.21.0.0/16 开始递增
miniblog-network:      172.21.0.0/16
user-service-network:  172.22.0.0/16
order-service-network: 172.23.0.0/16
payment-network:       172.24.0.0/16
```

## 常用场景

### 场景 1: 单主机开发环境

```bash
# 1. 创建业务网络
make app-network-create NAME=miniblog-network

# 2. 在应用的 docker-compose.yml 中使用
cat > docker-compose.yml <<EOF
version: '3.8'

services:
  miniblog-app:
    image: miniblog:latest
    networks:
      - miniblog-network
      - infra-network

networks:
  miniblog-network:
    external: true
    name: miniblog-network
  infra-network:
    external: true
    name: infra-network
EOF

# 3. 启动应用
docker-compose up -d

# 4. 验证网络连接
docker exec miniblog-app ping mysql
docker exec miniblog-app ping redis
```

### 场景 2: 跨主机生产环境

```bash
# ServerA (192.168.1.100) - 管理节点
# 1. 初始化Swarm
make swarm-init ADVERTISE_ADDR=192.168.1.100

# 2. 创建基础设施overlay网络
make swarm-network

# 3. 创建业务overlay网络
make app-network-create NAME=miniblog-network DRIVER=overlay ATTACHABLE=true

# ServerB (192.168.1.101) - 工作节点
# 1. 加入集群
make swarm-join MANAGER_IP=192.168.1.100

# ServerA - 验证
# 2. 查看集群状态
make swarm-status
make swarm-nodes

# 3. 部署应用（overlay网络自动同步到所有节点）
docker stack deploy -c docker-compose.yml miniblog
```

### 场景 3: 内部隔离网络

```bash
# 创建内部网络（容器间可通信，但无法访问外部）
make app-network-create NAME=db-cluster INTERNAL=true

# 用于数据库集群内部通信
cat > docker-compose.yml <<EOF
version: '3.8'

services:
  mysql-master:
    image: mysql:8.0
    networks:
      - db-cluster
      - infra-network

  mysql-slave:
    image: mysql:8.0
    networks:
      - db-cluster

networks:
  db-cluster:
    external: true
    name: db-cluster
  infra-network:
    external: true
    name: infra-network
EOF
```

### 场景 4: 加密传输

```bash
# 创建加密overlay网络（适用于敏感数据跨主机传输）
make app-network-create NAME=payment-network \
  DRIVER=overlay \
  ENCRYPTED=true \
  ATTACHABLE=true
```

## 故障排查

### 问题 1: 网络已存在

**错误**: `network with name XXX already exists`

**解决**:

```bash
# 查看现有网络
make app-network-list

# 删除冲突网络
make app-network-delete NAME=XXX

# 重新创建
make app-network-create NAME=XXX
```

### 问题 2: 无法创建overlay网络

**错误**: `This node is not a swarm manager`

**解决**:

```bash
# 先初始化Swarm
make swarm-init ADVERTISE_ADDR=你的IP

# 再创建overlay网络
make app-network-create NAME=XXX DRIVER=overlay
```

### 问题 3: 容器无法通信

**检查步骤**:

```bash
# 1. 确认网络存在
make app-network-list

# 2. 确认容器在同一网络
docker network inspect miniblog-network

# 3. 测试连通性
docker exec container1 ping container2

# 4. 检查防火墙
# Swarm需要开放: 2377, 7946, 4789端口
```

### 问题 4: 删除网络失败

**错误**: `network has active endpoints`

**解决**:

```bash
# 查看使用该网络的容器
docker network inspect XXX | grep Containers -A 20

# 停止相关容器
docker stop container_name

# 或断开连接
docker network disconnect XXX container_name

# 重新删除
make app-network-delete NAME=XXX
```

### 问题 5: Swarm节点无法加入

**检查清单**:

```bash
# 1. 检查防火墙端口
sudo firewall-cmd --list-ports
# 需要开放: 2377/tcp, 7946/tcp, 7946/udp, 4789/udp

# 2. 检查管理节点状态
make swarm-status

# 3. 重新获取join token
docker swarm join-token worker
docker swarm join-token manager

# 4. 检查时间同步
timedatectl status
```

## 💡 最佳实践

### 1. 命名规范

```bash
# ✅ 推荐: 应用名-network
miniblog-network
user-service-network

# ❌ 避免: 通用名称
app-network
network1
```

### 2. 网络选择

```bash
# 单主机: 使用 bridge（性能更好）
make app-network-create NAME=app-net DRIVER=bridge

# 跨主机: 使用 overlay
make app-network-create NAME=app-net DRIVER=overlay ATTACHABLE=true
```

### 3. 安全性

```bash
# 内部服务使用 internal 网络
make app-network-create NAME=db-internal INTERNAL=true

# 跨主机敏感数据使用加密
make app-network-create NAME=payment DRIVER=overlay ENCRYPTED=true
```

### 4. 子网规划

提前规划子网，避免冲突：

- 基础设施: `172.20.0.0/16`
- 业务应用: `172.21.0.0/16` 开始递增
- 预留空间: 每个应用独立 `/16` 网段
