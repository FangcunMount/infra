## 具名操作边界

目标为原 Aliyun RDS MySQL 8.0.36 的当前应用账号；不更改端点、账号名、认证插件、权限、业务表或连接池预算。生产采用先停全部相关写者、后一次变更的方式，不建立双密码共存机制。serverA 和 serverD 上八个业务进程及其三阶段配置一并绑定新凭据。自动生产 CD 继续暂停；重新启用之前须核对原部署凭据入口已同步。

新旧密码和准确 server UUID、CURRENT_USER、版本、CA 与有效期写入私有0600计划，独立核对原始SHA-256。新密码独立随机生成；旧值不放进CLI、shell历史或CI。计划不证明停写或批准，生产仍须由最终具名清单和单一协调器控制。

工具 `scripts/ops/m3_mysql_credential.py` 默认 preview，只使用旧凭据读取身份、TLS和权限摘要。apply 要求明确停写及首次启动屏障已发出的声明；外层受审协调器负责证明这些事实、持有原主机部署锁及保护实际步骤。该工具不启动业务、不关闭准入、不生成审批，也不能自行跨过协调器。

1. 全部旧业务写者、Relay、自主任务停止；原消息和未来计划已完成处置/交接，离线迁移及恢复材料就绪。
2. 单一协调器记录首次新runtime启动步骤，随后在该步骤中执行一次凭据变更和最终镜像启动。记录后即使变更或启动失败，也不恢复旧全量备份覆盖当前事实。
3. apply 先读取并验证准确的 server UUID、版本、CURRENT_USER、TLS 和权限摘要；fsync一次性 issued marker 后，仅发送一次 `SET PASSWORD ... REPLACE ...`。
4. 关闭旧连接；新建连接证明新凭据及原身份/权限不变，再以全新连接验证旧凭据收到明确1045。网络错误不能冒充拒绝。
5. 回复丢失时只验证当前事实，不重复发送密码语句，不改回泄露旧值。已发出操作后非零退出视为未查清；只允许 `--action verify` 和具名排障。

密码更新采用当前账号的 [MySQL SET PASSWORD](https://dev.mysql.com/doc/refman/8.0/en/set-password.html) 语义，保留认证插件；不使用会切换到默认认证插件的账号重建操作。实测必须包含 mysql_native_password 和 caching_sha2_password、主机名验证TLS及真实旧凭据拒绝。
