## 有界用例与核验

1. **窗口前准备**：批准后沿原合法业务入口只准备上述专用单轮计划模板，不加入受试者、不提前开放新Task；读取原合法填写入口规则与模型版本。新Task关联/开放放在新runtime验收阶段，避免用旧NSQ的Task事件冒充RocketMQ证明。仅准备新测试数据，不提交答卷、不将NSQ准备行为算作新RocketMQ验收。明确核验填写端是否有可用合法会话；后台system登录不代表小程序/填写端已经登录。若需用户正常登录或操作，必须在停机前补齐，不能在窗口里临时伪造身份或等待不明认证。
2. **授权变更**：新版本运行后，system在原后台创建/更新空角色。精确关联操作、策略版本、Committed witness与两端实际消费/加载版本；一个消费者成功不能代替全部收敛。若后台不显示Operation-ID，可由受限只读证据精确关联新角色和操作，不导出凭据或改写证据。
3. **答卷→评分→报告**：新runtime就绪后，将上述测试受试者加入专用单轮计划，等待新Task真实开放；沿正常填写入口仅提交一份明确的合成答案。核对真实202与持久化答卷、原幂等结果、Mongo witness；再核对Run/Outcome/Generation/Report及各自MySQL witness和消费者效果。刷新/重复读取只观察原结果；不通过第二次新提交或直接重放数据库记录补失败。
4. **QS↔AI**：仅使用新测评产生的正常业务命令，核对首次command档案、AI receipt/state、QS Inbox/投影/ACK及双方witness。沿原provider预算执行，不新增故障注入、手工retry或模型调用授权；不确定provider结果进入原治理，不能为了验收重新调用模型。
5. **Task及通知**：记录新Task真实开放、绑定与内部提醒事件。不得向真实手机号、微信联系人或外部群发送验收通知；原链路若不能保证隔离外部联系人，则在维护前停止该用例并收敛方案。内部事件提交不冒称外部提醒已送达。原Task故障/幂等证据继续保留。
6. **通过后开放**：四owner绑定/Checker/消费者健康、上述事实/receipt实际核验后恢复原三个入口。保留acceptance运行配置，不为open目录名称再重启。T33完成与随后48小时观察分别记录；源CI、登录和旧链路测试均不替代它们。
