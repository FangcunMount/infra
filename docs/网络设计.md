# 基础设施网络设计

## 网络架构

本项目采用**单一 Overlay 网络**设计，支持跨服务器的分布式部署。

### 网络: infra-network

- **用途**: 所有基础设施服务的分布式通信网络
- **驱动**: overlay (支持跨主机通信)
- **子网**: `172.20.0.0/16`
- **网关**: `172.20.0.1`
- **MTU**: 1500 (可配置)
- **加密**: 启用 (encrypted=true)
- **可附加**: 启用 (--attachable，允许独立容器连接)
- **标签**:
  - `infra.network=backend`
  - `infra.purpose=distributed-service-communication`

## 为什么使用 Overlay 网络？

1. **跨主机通信**: NSQ 等分布式服务需要在多台服务器间通信
2. **Docker Swarm 支持**: 原生支持 Swarm 集群部署
3. **服务发现**: 自动 DNS 解析，服务可通过名称互相访问
4. **负载均衡**: 内置负载均衡和故障转移
5. **安全加密**: 支持网络流量加密传输

## 连接的服务

所有基础设施服务都连接到 `infra-network`:

- **Nginx** - Web 服务器和反向代理
- **MySQL** - 关系型数据库
- **Redis** - 缓存和会话存储
- **MongoDB** - 文档数据库
- **Kafka** - 消息队列
- **NSQ** - 轻量级消息队列
- **Jenkins** - CI/CD 服务器

## 端口映射

服务通过宿主机端口映射对外暴露：

| 服务 | 内部端口 | 外部端口 | 说明 |
|------|---------|---------|------|
| Nginx | 80, 443 | 80, 443 | HTTP/HTTPS |
| MySQL | 3306 | 3306 | 数据库连接 |
| Redis | 6379 | 6379 | 缓存连接 |
| MongoDB | 27017 | 27017 | 文档数据库 |
| Kafka | 9092 | 9092 | 消息队列 |
| NSQ | 4150-4171 | 4150-4171 | NSQ 各组件端口 |
| Jenkins | 8080, 50000 | 8080, 50000 | Web UI 和 Agent |

## 网络管理命令

### 初始化网络
```bash
make init              # 完整初始化（网络+卷）
make network-init      # 仅初始化网络
```

### 查看状态
```bash
make network-status    # 查看网络状态
make network-list      # 列出所有网络
```

### 重置网络
```bash
make network-reset     # 删除并重建网络
```

### 检查网络详情
```bash
make network-inspect NAME=infra-network
```

## 设计说明

### Overlay vs Bridge

**为什么不用 Bridge？**
- Bridge 网络仅限于单台主机
- 无法支持跨服务器的服务通信
- 不适合分布式部署场景

**Overlay 网络优势**
1. **跨主机通信**: 容器可以在不同服务器间通信
2. **服务发现**: 自动 DNS 解析
3. **负载均衡**: 内置流量分发
4. **安全性**: 支持加密传输
5. **扩展性**: 易于横向扩展

### 前置要求

使用 Overlay 网络需要：
1. Docker Swarm 模式已初始化
2. 所有节点已加入 Swarm 集群
3. 管理节点配置正确

初始化 Swarm：
```bash
# 在管理节点执行
make swarm-init

# 在工作节点执行（使用管理节点提供的 token）
docker swarm join --token <token> <manager-ip>:2377
```

### 单机部署说明

即使在单机环境下，仍使用 Overlay 网络，原因：
1. 保持开发和生产环境一致
2. 便于后续扩展到多节点
3. 利用 Overlay 网络的服务发现功能

### 安全考虑

- 网络流量自动加密 (--opt encrypted=true)
- 与宿主机网络隔离
- 服务间通信通过内部 DNS
- 对外暴露的端口通过宿主机防火墙控制
- 敏感服务（如数据库）可以不映射外部端口

## 环境变量配置

可以通过环境变量自定义网络配置：

```bash
# 自定义子网
INFRA_BACKEND_SUBNET=10.10.0.0/16 make init

# 自定义网关
INFRA_BACKEND_GATEWAY=10.10.0.1 make init

# 自定义 MTU
INFRA_NETWORK_MTU=1450 make init
```

## 故障排查

### 网络无法创建
```bash
# 检查是否有网络冲突
docker network ls

# 检查子网是否被占用
docker network inspect bridge
```

### 服务无法通信
```bash
# 测试网络连通性
make network-status

# 查看服务网络配置
docker inspect <service_name> | grep -A 10 Networks
```

### 网络性能问题
```bash
# 检查 MTU 设置
docker network inspect infra-network | grep -i mtu

# 调整 MTU
INFRA_NETWORK_MTU=1450 make network-reset
```

## 迁移说明

如果之前使用了 `infra-frontend` 网络，需要进行迁移：

```bash
# 1. 停止所有服务
make down

# 2. 删除旧网络（如果存在）
docker network rm infra-frontend 2>/dev/null || true

# 3. 重置基础设施
make reset

# 4. 重新启动服务
make up
```
